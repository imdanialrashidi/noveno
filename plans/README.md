## Findings considered and rejected

- **Turnstile `upstream_error` → 500 (fail-closed)**: sound behavior, keep. Siteverify runs from Cloudflare's edge, not the client's network, so the Iranian-network concern affects widget load, not verification.
- **CSRF on `/api/audit`**: cross-site HTML forms cannot produce a valid JSON body; JSON content-type forces a CORS preflight; Turnstile gates real insertions. Not exploitable.
- **`cf-connecting-ip` spoofing / `X-Forwarded-For`**: Cloudflare sets the header; clients cannot forge it.
- **CORS**: neither endpoint emits `Access-Control-Allow-Origin` — same-origin only, correct.
- **Web3Forms client-side posting**: documented free-tier decision (docs/PLAN.md evidence ledger); residual PII-to-third-party risk noted in plan 002's maintenance notes. Plans 021+028 revisit the vector after the email-only cutover.
- **RSS feed (direction, 2026-08-15)**: previously rejected as near-zero demand for Persian SMB; re-evaluated as plan 029 after `/blog` shipped with real content — spike retained as TODO, reject again only if founder confirms no demand.
- **npm audit via npmmirror**: registry lacks the audit endpoint; resolved by plan 006 (official-registry lockfile + guard), which makes `npm audit` meaningful again (verified 2026-08-21: `npm audit` on official registry → 0 vulns).
- **Future first_seen_at as invalid_date (2026-08-21)**: was a bug, not by-design — fixed in plan 020. Ancient timestamps already dropped; future skew now drops too.
- **Analytics Engine metered writes are PII-free**: payload keys are `EVENT_PAYLOAD_KEYS` only (no name/phone/email) — verified in `tests/audit-function.test.mjs` PII-free contract; plan 031 keeps it.
