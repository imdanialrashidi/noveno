## Findings considered and rejected

- **Turnstile `upstream_error` → 500 (fail-closed)**: sound behavior, keep.
  Siteverify runs from Cloudflare's edge, not the client's network, so the
  Iranian-network concern affects widget load, not verification.
- **CSRF on `/api/audit`**: cross-site HTML forms cannot produce a valid
  JSON body; JSON content-type forces a CORS preflight; Turnstile gates
  real insertions. Not exploitable.
- **`cf-connecting-ip` spoofing / `X-Forwarded-For`**: Cloudflare sets the
  header; clients cannot forge it.
- **CORS**: neither endpoint emits `Access-Control-Allow-Origin` —
  same-origin only, correct.
- **Web3Forms client-side posting**: documented free-tier decision
  (docs/PLAN.md evidence ledger); residual PII-to-third-party risk noted
  in plan 002's maintenance notes.
- **RSS feed (direction)**: the one missing piece of the editorial surface
  (~30 lines), but near-zero demand for a Persian SMB audience — not worth
  doing; record and move on.
- **npm audit via npmmirror**: registry lacks the audit endpoint; resolved
  by plan 006 (official-registry lockfile + guard), which makes `npm audit`
  meaningful again.
