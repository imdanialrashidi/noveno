## Why this matters

`scripts/generate-sitemap.mjs` (prebuild) re-derives the publish gate
(`draft`, `published_at`, `updated_at`) from frontmatter using a regex
mini-parser — the same parser class that mis-reads quoted values with
colons. The authoritative definition of "published" lives in the zod schema
in `src/content.config.ts`; the sitemap's phantom parse can disagree with it
for unusual-but-valid frontmatter (quoted strings, colons inside values).
The safety net (`tests/seo-contract.test.mjs` cross-checks sitemap ⇄ built
pages) contains drift, but the parser remains a silent trap. This plan swaps
the regex parser for real YAML (the `yaml` package, added to dependencies by
this plan) and adds a defect-sensitive test.

## Current state

- `scripts/generate-sitemap.mjs:36-57`:
  ```js
  function parseFrontmatter(file) {
    const raw = readFileSync(file, "utf8");
    const match = /^---\r?\n([\s\S]*?)\r?\n---/.exec(raw);
    if (!match) return {};
    const data = {};
    for (const line of match[1].split(/\r?\n/)) {
      const kv = /^([a-z_]+):\s*(.*)$/.exec(line.trim());
      if (!kv) continue;
      const key = kv[1];
      const value = kv[2].trim().replace(/^"|"$/g, "");
      data[key] = value === "true" ? true : value === "false" ? false : value;
    }
    return data;
  }
  ```

### Step 2: Swap the parser

In `scripts/generate-sitemap.mjs`:

```js
import YAML from "yaml";

function parseFrontmatter(file) {
  const raw = readFileSync(file, "utf8");
  const match = /^---\r?\n([\s\S]*?)\r?\n---/.exec(raw);
  if (!match) return {};
  const data = YAML.parse(match[1]);
  return data && typeof data === "object" ? data : {};
}
```

Also export the function for tests (`export function parseFrontmatter`).
Update the module docstring: "frontmatter parsed with real YAML (matches
the zod schema semantics — quoted values and colons parse correctly)".

Check downstream usage: `contentEntries` reads `data.draft`,
`data.published_at`, `data.updated_at`. YAML gives real booleans for
`draft: true` (same truthiness as before) and strings for dates (the
generator must format them — verify the current string handling still
works; if the old parser produced e.g. `2026-10-01` and YAML produces the
same string, nothing changes).

**Verify**: `node scripts/generate-sitemap.mjs` → exit 0, and

### Step 3: Defect-sensitive parser test

Create `tests/sitemap-parser.test.mjs` importing
`parseFrontmatter` from `../scripts/generate-sitemap.mjs`:

```js
test("parseFrontmatter handles quoted colons and arrays (real YAML)", () => {
  const dir = fs.mkdtempSync(path.join(os.tmpdir(), "noveno-sitemap-"));
  try {
    const file = path.join(dir, "x.md");
    fs.writeFileSync(file, '---\ntitle: "A: quoted title"\ncanonical: https://example.com/a:b\ndraft: false\ntags:\n  - one\n  - two\n---\n');
    const data = parseFrontmatter(file);
    assert.equal(data.title, "A: quoted title");
    assert.equal(data.canonical, "https://example.com/a:b");
    assert.equal(data.draft, false);
    assert.deepEqual(data.tags, ["one", "two"]);
  } finally {
    fs.rmSync(dir, { recursive: true, force: true });
  }
});

test("parseFrontmatter returns {} for missing frontmatter", () => {
  const dir = fs.mkdtempSync(path.join(os.tmpdir(), "noveno-sitemap-"));
  try {
    const file = path.join(dir, "x.md");
    fs.writeFileSync(file, "no frontmatter here\n");
    assert.deepEqual(parseFrontmatter(file), {});
  } finally {
    fs.rmSync(dir, { recursive: true, force: true });
  }
});
```

The first test fails on the old regex parser (colon inside quoted value
splits the line) — defect sensitivity.

**Verify**: `node --test tests/sitemap-parser.test.mjs` → all pass.
