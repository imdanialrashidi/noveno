## Why this matters

`npm run build` (prebuild hook) runs `scripts/build-image-manifest.mjs`,
which prunes "stale hashed copies" under `public/images/`. Its classifier
treats ANY image whose name ends in `.<8-hex-chars>.<ext>` as a generated
hash copy. A founder-named logical file like
`public/images/work/hero-1234abcd.webp` (a perfectly reasonable name —
e.g. a download or a hex-ish slug) matches the pattern and, because it was
not generated by this run, is **silently deleted with `rmSync`** during a
routine build. Unrecoverable, and referenced images 404 in production. The
fix makes pruning conservative: only delete a candidate whose base name
matches a logical (source) file in the same directory — which is exactly how
generated hashed names are constructed.

## Steps

### Step 1: Extract a conservative prune classifier

In `scripts/build-image-manifest.mjs`:

1. Add a pure, exported function:

```js
/**
 * Decide which files may be pruned as stale generated variants.
 * A file is prunable ONLY when its name is `<basename>.<8-hex>.<ext>`
 * AND `<basename>` is a logical (source) file's basename in the SAME
 * directory — generated hashed copies are always created that way.
 * A founder-named file that merely looks hashed (e.g. hero-1234abcd.webp
 * with no logical hero-1234abcd source) is never pruned.
 * Trade-off: a stale variant whose logical source was deleted is kept
 * (bounded accumulation) rather than risking a wrong deletion.
 */
export function collectPrunableCandidates(allFiles, logicalFiles) {
  const logicalBasesByDir = new Map();
  for (const file of logicalFiles) {
    const dir = file.slice(0, file.lastIndexOf("/") + 1);
    const base = file.slice(file.lastIndexOf("/") + 1).replace(/\.[^.]+$/, "");
    if (!logicalBasesByDir.has(dir)) logicalBasesByDir.set(dir, new Set());
    logicalBasesByDir.get(dir).add(base);
  }
  return allFiles.filter((file) => {
    if (!HASHED_RE.test(file)) return false;
    const slash = file.lastIndexOf("/");
    const dir = file.slice(0, slash + 1);
    const name = file.slice(slash + 1);
    const base = name.replace(HASHED_RE, "");
    return logicalBasesByDir.get(dir)?.has(base) === true;
  });
}
```

2. Replace the prune loop with:

```js
/* Prune stale hashed copies — conservatively (see collectPrunableCandidates). */
for (const file of collectPrunableCandidates(allFiles, logical)) {
  if (!liveHashed.has(file)) {
    rmSync(file);
    console.log(`pruned stale variant: ${file.slice(IMAGES_DIR.length + 1)}`);
  }
}
```

3. Update the module docstring ("Stale hashed copies ... are pruned" →
   add "only when their base name matches a logical file in the same
   directory; founder-named files that merely look hashed are never
   pruned").

Note the paths use `/` separators (the script already normalizes with
`replaceAll("\\", "/")` on logical paths; `walk()` returns OS-native paths —
use `path.sep`-safe handling by normalizing with the same replaceAll before
computing dir/base, to stay Windows-safe).

**Verify**: `npm run build` → exit 0, and `git status --porcelain` shows no
deleted files under `public/images/`.
